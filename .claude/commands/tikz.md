# TikZ validation

Validate the provided TikZ code or the .tikz/.tex file open in the IDE with the `figure-review` skill. The rules are
not kept here: read `.claude/skills/figure-review/assets/figure_criteria.json` and judge every criterion whose
`applies_to` contains `tikz` (`tikz_node_line_breaks`, `tikz_backgrounds_scaling`, `tikz_arrows_clear_of_shapes`,
`tikz_arrows_not_overlapping`, `tikz_arrows_perpendicular`, `tikz_shapes_min_distance`, `tikz_arrow_text_no_overlap`,
`tikz_anchored_positioning`, `tikz_simple_for_tikzit`). A criterion whose `needs` is `source` is judged on the code, a
criterion whose `needs` is `image` on the rendered picture.

**Render option.** Judging an `image` criterion needs a PNG of the figure: `figure_render.py --tex FILE --out DIR
--render`. It is off by default; the user turns it on with `--render` in the arguments. Without it, judge the `source`
criteria on the code and say which `image` criteria were not judged.

**Exception - drawio2tikz output:** a figure generated by the `drawio2tikz` skill (a coordinate-exact `.drawio`
conversion) uses absolute coordinates and inline colours by design. Do not flag `tikz_anchored_positioning` or
`tikz_simple_for_tikzit` for it; still check every other criterion.

For each violation: cite the line, explain the cause in one sentence, provide the corrected code directly.
If no issues are found: confirm in one line.
