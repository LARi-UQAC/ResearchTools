    Profiles & Environment¶

    Chapter 02 of the ResearchTools manual. Back to table of contents.

    Profiles¶

    A domain profile centralizes everything domain-specific (Scopus subject areas and exclusions, topical-relevance signals, off-topic flag, stats profile, author, course context, language) in one YAML file under profiles/, so the agents and skills stay shared across users and labs: one maintained core, N profiles.

    Profile Domain Author Default
    engineering.yaml Mechanical / electrical / ML / control / systems engineering Martin Otis (UQAC) yes
    cosmetic.yaml Cosmetic / formulation science (SPF, microbiome, dermatology, sensory) Lionel Ripoll (UQAC) no
    _template.yaml Copy it to profiles/<domain>.yaml to add a new domain - -

    The active profile is recorded in .claude/CLAUDE.md as the machine-readable line active_profile: <name>. Select it at install time (.\install.ps1 -Profile <name>, or the interactive prompt) or edit that line directly. Currently wired consumer: scopus-researcher (search clauses, Step 3a relevance check, synthesis framework); the remaining fields (author, stats_profile, course_context, language) are schema-ready and will be wired incrementally. Field-by-field spec, fallback rules, and the add-a-profile procedure: profiles/README.md.

    Environment variables / API keys¶

    Set these at the Windows User scope (PowerShell), then restart Claude Code:

    [System.Environment]::SetEnvironmentVariable('SCOPUS_API_KEY', 'your-key', 'User')
    Variable / source Required for Where to get it
    SCOPUS_API_KEY Required — all /scopus, /auditreview, /auditpaper, /auditthesis, /litreview, /litupdate, /bibclean, /replyreviewer, and PDF retrieval Elsevier Developer Portal
    .scopus_key file Fallback for SCOPUS_API_KEY — place the key in .claude/skills/scopus/.scopus_key (gitignored) same key as above
    UNPAYWALL_EMAIL Optional — enables the Unpaywall open-access tier in download_pdf.py (HTML/PDF fallback when no publisher PDF); a plain contact email, or pass --email any institutional email
    GEMINI_API_KEY Optional — the Gemini leg of the deliberation panel (cross-review, table enrichment). The model is resolved at run time from Google's own catalogue (--gemini-model auto), so no model name is set here Google AI Studio
    COPILOT_TOKEN or GH_OAUTH_TOKEN Optional — the GitHub Copilot leg of the deliberation panel. GH_OAUTH_TOKEN is exchanged automatically for a Copilot token. Without either, the panel uses a local Ollama model declared for the session role as the second voice, and without that too the leg is skipped without stopping the pipeline your GitHub account with Copilot
    GITHUB_TOKEN Legacy — Copilot refuses a personal access token and GitHub Models was retired on 2026-07-30, so this variable no longer gives a cross-review leg. It is still the last attempt of the provider chain GitHub → Settings → Developer settings
    S2_API_KEY (or SEMANTIC_SCHOLAR_API_KEY) Optional — Semantic Scholar author/PDF backfill; without it the throttled public pool is used Semantic Scholar API key request
    --insttoken (CLI flag, not an env var) Optional — off-campus Elsevier access when not on the UQAC network/VPN UQAC library / Elsevier institutional token

    An on-campus network connection or active UQAC VPN is required for Scopus access unless an --insttoken is supplied. Secrets are kept out of git: .env, secrets/, and credentials/ are listed in .gitignore.

    Python environments: every library¶

    A skill that imports a library nobody declared works on the machine that happens to have it and fails on every other one, so this section lists every third-party library the repository's Python code needs, one row per library. It was built on 2026-10-22 by reading the import statements of all 404 .py files (skills, hooks, scripts and tests, but not docs/superpowers/), then comparing them with every requirements file and with what each environment really holds. The environments are two: .venv-skills, for the skills, the hooks' tests and the offline suite, and .venv-docs, for this site. A library used in both has a row in each table with its own version, since the two environments are independent and do not always agree.

    How to read the tables:

    • ☑ in the first column means the library is declared in a requirements file. ☐ means the code uses it and no file declares it, and the note says why.
    • "Version" is what the environment holds on this machine on 2026-10-22, measured with pip list, and not the version a fresh install would resolve.
    • (added) marks a line added to a requirements file on 2026-10-22 because the code imported the library and no file declared it.
    • A library that is optional in code (a guarded or lazy import) is marked optional.
    • Programs that are not pip packages (pandoc, Poppler, MiKTeX, Ollama, Node.js) are in the Prerequisites table of chapter 01.

    .venv-docs¶

    Python 3.13.3 on this machine. It is created by hand, setup.ps1 does not create it: see chapter 16. It holds the 40 pinned lines of requirements-docs.txt plus pip, and the installed versions match the pins exactly. The site needs mkdocs and mkdocs-material (the theme), pymdown-extensions and Markdown (the extensions listed in mkdocs.yml: attr_list, md_in_html, tables, toc, pymdownx.superfences, pymdownx.highlight and pymdownx.slugs), ghp-import (the gh-deploy command) and PyYAML. The build hook scripts/docs/mkdocs_hooks.py uses the standard library only.

    Eleven lines are marked orphan: nothing installed in this environment requires them, or they are required only by another orphan. They are not needed to build the site. Their set matches the dependencies of pip-audit, which suggests a past install of it, but that is an inference and not checked. They are left in requirements-docs.txt for now.

    A third environment¶

    deploy/form-service/ has its own environment, %LOCALAPPDATA%\ResearchTools\venv-form-service, described by deploy/form-service/requirements.txt: fastapi==0.141.1, uvicorn==0.54.0, pypdf==6.19.0, pyHanko==0.37.0, cryptography==50.0.1 and requests==2.34.2. Two of them differ from .venv-skills, which holds fastapi 0.159.1 and cryptography 50.0.2. The service tests run in that environment, not in .venv-skills.

    Keeping these tables true¶

    No script regenerates them. A library added to a skill without a line in its requirements file is exactly the gap this section was written to close, so a change that adds an import of a new third-party library also adds the line, with an exact version checked by pip-audit (chapter 16), and one row here.
